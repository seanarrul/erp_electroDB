# Student Setup (No Docker)

This guide explains how to run the HOPE Group4 Sales and Payments Monitoring System locally for coursework and demonstration.

**Docker is not required.** The local application uses the existing SQLite demo database and Node.js.

## 1. Prerequisites

Install the following:

- Node.js 22.5.0 or newer.
- npm, which is included with Node.js.
- Git.

Check your installation:

~~~powershell
node --version
npm.cmd --version
~~~

## 2. Get the project

Clone the repository:

~~~powershell
git clone https://github.com/seanarrul/erp_electroDB.git
cd erp_electroDB
~~~

If the project is already downloaded, open PowerShell in its existing folder.

## 3. Install dependencies

On Windows PowerShell:

~~~powershell
npm.cmd ci
~~~

On Windows Command Prompt, macOS, or Linux:

~~~bash
npm ci
~~~

This installs dependencies recorded in package-lock.json.

If PowerShell blocks the npm command because of its script execution policy, use npm.cmd instead. You do not need to change the computer's execution policy.

## 4. Verify the local demo database

Run the existing read-only verification script:

~~~powershell
node .\scripts\verify-db.mjs
~~~

On macOS or Linux:

~~~bash
node scripts/verify-db.mjs
~~~

The script checks the local hope.db file, database connectivity, the ten canonical business tables, and their expected row counts. It does not modify database records.

The project also creates and uses a separate auth.db database for local authentication data.

Do not delete or replace hope.db. If the database file is missing or verification fails, contact the project maintainer rather than importing another dataset or running destructive SQL scripts.

## 5. Start the development server

On Windows PowerShell:

~~~powershell
npm.cmd run dev
~~~

On Windows Command Prompt, macOS, or Linux:

~~~bash
npm run dev
~~~

Open this address in your browser:

http://localhost:3000

To stop the development server, return to the terminal and press Ctrl+C.

## 6. Database and migration notes

The local coursework/demo setup uses the SQLite database files included or generated by the application. Docker is not needed.

The numbered SQL files in database/migrations are PostgreSQL migration scripts. They are not automatically executed by npm run dev.

Do not run migration scripts against a shared Supabase project or replace existing database objects without approval from the project maintainer.

Supabase/PostgreSQL deployment is a separate setup process. Follow the main project README and the team's approved deployment instructions when that environment is required.
